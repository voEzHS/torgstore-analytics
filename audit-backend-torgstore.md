# TorgStore Analytics — аудит бэкенда

Дата аудита: 26 июля 2026. Дата исправлений: 26 июля 2026 (тот же день). Статус ниже по каждому пункту.

## Оставлено как есть — по решению пользователя

**1. Авторизация.** Сайт локальный, наружу не смотрит — по прямому решению пользователя авторизацию не добавляем. CORS (`allow_origins=["*"]`) оставлен по той же причине: без авторизации отдельное закрытие CORS не даёт реальной защиты, только ложное ощущение безопасности. Если сайт когда-либо станет доступен не только с localhost — к этим двум пунктам нужно будет вернуться.

## Исправлено сегодня

**2. Управление миграциями.** `backend/core/migrate.py` переписан: теперь таблица `schema_migrations` отслеживает, какие файлы из `migrations/*.sql` применены, и при старте автоматически накатываются все ещё не применённые — по порядку, а не только `001_initial_schema.sql`. Бэкфилл для перехода со старой логики: если `managers` уже существует, 001 помечается применённой без повторного запуска (она не идемпотентна), а 002-005 (идемпотентны) применяются повторно безопасно и с этого момента тоже попадают под отслеживание. Неиспользуемая зависимость `alembic` убрана из `requirements.txt`.

**3. Мёртвый код удалён.** Роутеры `customers.py` и `sales.py`, модели `Customer`/`Sale`/`AuditLog` — удалены из кода. Добавлена миграция `006_drop_unused_tables.sql` (`DROP TABLE IF EXISTS sales, customers, audit_log`), применится автоматически при следующем старте через новый механизм миграций.

**4. `POST /import/tree-json` теперь валидирует форму ответа CRM.** `total` в `TreeImportIn` — больше не произвольный `Dict[str, Any]`, а Pydantic-модель с обязательными полями `leads`/`sales`/`revenue` (без дефолта). Если CRM переименует или уберёт одно из этих полей — эндпоинт вернёт понятную 422-ошибку с именем недостающего поля вместо того, чтобы молча записать 0 всем менеджерам. Проверено вручную: корректный payload проходит, payload с переименованным `revenue` → `total_revenue` корректно падает с `Field required`.

**5. Overrides теперь сами инвалидируют кэш.** `PUT /overrides` и `DELETE /overrides/{id}` вызывают `compute_and_cache` сразу после записи — эндпоинт больше не полагается на то, что вызывающая сторона отдельно дёрнет `/recalculate`.

**6. Единая обработка UUID.** Все прежде необёрнутые `uuid.UUID(...)` (в `managers.py`, `sessions.py`, `sources.py`, `overrides.py`) теперь дают чистую 400-ошибку с текстом, а не голый 500 на битом ID.

**7. Убрано дублирование parse_period.** `period_targets.py` больше не содержит свою слабую копию (молча дефолтившую на 2026/Январь при плохом формате) — переиспользует `imports.parse_period`, который явно поднимает ошибку.

**8. Хардкод DB-кредов убран.** `core/database.py` больше не подставляет `postgres:password@localhost` по умолчанию — без `DATABASE_URL` приложение явно падает при старте с понятной инструкцией, а не тихо цепляется не туда. В текущем docker-compose `DATABASE_URL` всегда задан, так что рабочий сетап не затронут.

**9. N+1 в `sessions.py` устранён.** `GET /sessions` теперь делает один запрос на все `PeriodTarget` вместо отдельного запроса на каждую сессию в цикле.

**10. AI-кэш больше не растёт бесконечно.** В `ai.py` добавлен верхний предел (`_CACHE_MAX_ENTRIES = 200`) с вытеснением самой старой записи.

**11. Мелочи.** `.dict()` → `.model_dump()` в `sources.py` (Pydantic v2 без deprecation-предупреждений); `POST /managers` теперь проверяет уникальность имени среди активных менеджеров (регистронезависимо) и возвращает 409 на дубликат.

Проверено: приложение импортируется целиком без ошибок (`backend.main`), маршруты `/customers` и `/sales` из списка роутов пропали, SQLAlchemy `configure_mappers()` проходит без ошибок висящих связей.
